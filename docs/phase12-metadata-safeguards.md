# Phase 12：服务层硬编码语义兜底迁移

按用户要求跳过 Phase 11，先完成这一步的**服务层**迁移；没有执行真实模型案例，也不据此声称官方集准确率保持不变。

`QueryService._apply_rule_plan_safeguards()` 原先用一份中文业务词表强制替换模型 QueryPlan。这会让新增术语无法泛化，也会让评测结果混入固定题词命中。本阶段移除该词表和 `_required_output_metrics()` 的指标词组字典。当前只针对通用的缺失指标、输出字段、分组粒度、不必要澄清和未解析过滤做结构保护：运行时待补指标必须在当前检索的 active metric metadata 中，且输出指标由结构化 `QueryOutput.columns` 决定，不再靠 Python 的关键词映射猜测。业务阈值、过滤和来源仍由 `ground_query_plan()` 与 QueryPlanHardValidator 对照 active metadata 证据校验；SQL 只读、字段白名单、敏感字段等硬安全规则不变。

原有 `RuleBasedQueryPlanActor` 作为系统已有兜底保留，没有按“删掉假模型”的方式误删。它内部仍有领域规则，因此**不能说整个系统已经完全摆脱 Python 业务规则**；本阶段清理的是方案明确点名的服务层强制覆盖与输出词表。下一次删除更深层的规则前，必须取得真实回归证据。若检索上下文缺少指标定义，本阶段宁可让计划校验失败或要求补足上下文，也不将未经 metadata 证实的规则指标硬塞进计划。

验收包括新增的自定义指标通用测试、无元数据定义时不强制补齐测试、筛选指标不误入输出测试，以及现有完整后端回归。真实模型回归需要用户之后明确安排；本次不运行或存储评测结果。
